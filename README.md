## 一、先分清四种"IPv6 VPS"，选错方向后面全错

**双栈 VPS**：同时有 IPv4 和 IPv6。注意，套餐写着支持 IPv6 不等于已经开好。以搬瓦工为例，你需要在 KiwiVM 面板左侧找到 IPv6 network，点 Activate /64 IPv6 subnet，看到成功提示后重启 VPS，再 `ifconfig` 看到 `inet6` 才算生效。如果当前机房不在支持列表里，面板会直接甩给你一句 `IPv6 is not available at this location. Please consider migrating your VM to an IPv6-ready data center.`——意思是先迁机房，再回来激活。这套流程说明了一件事：**"套餐支持 IPv6"和"你现在就能用 IPv6"是两回事**，中间隔着一次手动操作。

**纯 v6 only**：只分配 IPv6，没有任何 v4 通道。这类机器最便宜，但连 `apt update` 都可能卡在 v4 源上，GitHub raw、部分 Docker 镜像源同样拉不动。适合已经知道自己要干什么的人，不适合第一次买。

**纯 v6 但附带 v4 出口**：商品页有时会写成"v6 v4 v6"这种别扭的标记，意思是主体是 v6，但给你留了一条 v4 出口。对新手友好度差别巨大，日常装软件、跑脚本基本不受影响，能省掉一整轮 DNS64 和 WARP 的配置。

**NAT 型**：IPv4 只开放指定端口，IPv6 全端口开放。ByteVirt 的香港 NAT 机型就明确写了"仅能使用我们分配的 20 个 IPv4 端口，其他端口无法通过公网 IPv4 访问，IPv6 支持全端口开放"。这句话的实操含义是：你在这台机器上跑 Web 服务，走 IPv6 没问题，走 IPv4 就得挤在那 20 个端口里。这是 ByteVirt 自己的规则，不代表所有商家，但它精确解释了"NAT"两个字会给你带来什么限制。

## 二、五个必看指标，每个都配一个验证动作

### 1. 有没有 IPv4 出口

这是分水岭。有 v4 出口，你拿到机器就能 `ssh`、`apt`、`curl`，一切照旧；没有，你第一步就得改 `/etc/resolv.conf` 或者装 WARP。**验证动作**：翻商品页有没有写"附带 IPv4 出口""1 IPv4"，或者直接问客服。写着"1 IPv4 IP"就是有，写着"IPv6 only"就是没有，不含糊。

### 2. IPv6 路由质量，和 v4 路由不是一回事

同样是香港机房，v4 走 CN2 GIA 不代表 v6 也走同一条线路，这两张路由表经常是分开优化的。**验证动作**：找商家放出的测试 IP，用你自己本地有 v6 的网络 `ping6` 或 `mtr -6` 跑一遍，看延迟和丢包。别拿 v4 的测速结果推断 v6。

这一条对 LisaHost 尤其要留意：它的新加坡线路在商品页上写得很直白——"非中国大陆直连优化网络，部分地区联通和移动直连效果不错，建议通过香港或日本线路中转使用，香港延迟 30ms，日本延迟 70ms"。这是商家自己承认的定位，不是缺点，但你得知道：如果你买它是为了国内访问快，那你要么配中转，要么去看它的其他机房。

### 3. 流量规则：超额是停机还是降速

同样标"1000GB"，有的是用完直接断网，有的是把带宽降到最低但不断线，下月清零。后者对建站和长期跑服务友好得多。**验证动作**：商品页找"流量用完"的说明，找不到就问客服。LisaHost 新加坡各套餐的明细里只标了流量额度，超额处理方式没有公开写明，下单前值得问一句，尤其是你打算跑不限流量档之外的机型。

### 4. 商家运营时间和退款政策

v6 小鸡这个市场换手率很高。优先选运营时间长、退款条款写在明面上的。**验证动作**：看退款天数、是否有附加条件（流量用了多少、IP 是否完好、几次以内）。LisaHost 的新加坡套餐全部标注 **48 小时不满意无条件退款**，这个窗口不算长，够你跑完基础连通性测试和解锁验证，但不适合"用一个月再看看"的心态。

### 5. IPv6 到底能用几个地址

这一条最容易被忽略。很多商家宣传"分配 /64 子网"，听起来有 2 的 64 次方个地址，实际上手发现只能用几个。搬瓦工就是例子：面板给的是 /64，但实际可分配的独立 IPv6 地址上限是 3 个，需要手动分配；而 Vultr 的做法是把整段 /64 直接路由到你的网卡，段内地址随你用。两种机制都叫"/64"，能做的事差了一个数量级。

**验证动作**：直接问"给几个可用地址，是一段路由到网卡还是面板手动分配"。LisaHost 在这点上反而写得清楚：**5 个纯净原生 IPv6 地址**。不是一段，是 5 个。对多数人够用——5 个独立地址意味着你可以给 5 个服务或 5 个容器各绑一个，谁也不用挤 NAT。

## 五、买回来连不上？四条开荒路径和三个日常坑

**第一步，先确认你自己有没有公网 IPv6。** 浏览器打开 `https://ip.gs/`，能看到 v6 地址就说明本地通了。家里宽带现在多数默认开启，移动、电信光纤用户尤其如此；没有就去光猫或路由器后台把 IPv6 打开。这一步不做，你会以为是服务器的问题。

**第二步，没有 v4 出口就上 DNS64。** 编辑 `/etc/resolv.conf`，写入 Cloudflare 的 DNS64 地址：


nameserver 2606:4700:4700::64
nameserver 2606:4700:4700::6400


配 NAT64 网关后，纯 v6 机器能访问绝大多数 v4 网站，`apt update`、`curl`、`wget` 基本恢复正常。

**第三步，要更彻底就装 WARP。** wgcf 一键脚本能给机器加一条原生双栈出口，相当于凭空多出一个 v4 通道。Docker、Telegram 这类强依赖 v4 的服务，走这条路比 DNS64 更稳。LisaHost 自带原生 IPv4，这两步你可以直接跳过，但换成纯 v6 only 的机器时它们就是必修课。

**第四步，对外暴露服务。** 跑 Web，把域名解析到 IPv6 地址，开 Cloudflare 橙色云朵，CF 会自动给访客分配 v4 或 v6 入口再回源，只有 v4 的用户也能正常打开，顺带拿走 CDN 和 DDoS 防护。跑 SSH、自建 API 这种非 80/443 端口，用 Cloudflare Tunnel：机器上装 cloudflared 建隧道，把任意端口通过 CF 域名暴露出去，本地用 v4 就能连。Tunnel 还能反过来解决"本地没有 v6 却要连纯 v6 机器"的问题。

日常三个坑：

- **Docker 默认走 v4。** 纯 v6 机器上跑容器要改 `/etc/docker/daemon.json` 启用 ipv6，否则容器起得来但出不去。
- **老脚本可能硬编码了协议族。** 遇到莫名其妙的报错，先 grep 一下脚本里有没有写死的 IPv4 地址或 `AF_INET`。
- **监控命令要加 `-6`。** `ping`、`curl` 不加参数会默认走 v4，在纯 v6 机器上会一直失败，看起来像机器挂了。

## 七、FAQ

**纯 IPv6 VPS 本地连不上怎么办？**
三条路，按折腾成本从低到高：找一台有 v6 的跳板机，先 SSH 到跳板再连你的机器；装 Cloudflare Tunnel，本地用 v4 直连隧道；或者干脆换一台带 IPv4 出口的。买之前先上 `https://ip.gs/` 确认本地环境，能省掉这一整段。

**IPv6 要额外付费吗？**
多数商家免费。LisaHost 新加坡产品组页面明确写"免费送 5 个纯净原生 IPv6 地址"；德国机房则是提交工单免费申请 5 个原生 IPv6。搬瓦工也是免费分配。但要注意，套餐明细里通常只列 IPv4 数量，IPv6 写在产品组说明或需要工单申请，下单后主动确认一遍最稳。

**换机房之后 IPv6 地址会变吗？**
会。迁移机房通常意味着重新分配子网，旧地址失效，需要重新激活并更新 DNS 记录。如果你把 AAAA 记录指向了旧地址，记得同步改。

**`/64` 是不是整段都能用？**
不一定，取决于商家机制。搬瓦工给 /64 但实际可分配的独立地址上限是 3 个，要在面板手动分配；Vultr 是把整段 /64 路由到网卡，段内地址随你用。同样是"/64"，能做的事差很多，下单前问清楚是"整段路由"还是"手动分配几个"。LisaHost 直接写明给 5 个地址，反而没有这种歧义。

**Docker 在纯 v6 机器上怎么跑？**
改 `/etc/docker/daemon.json`，加上 ipv6 相关配置并重启 docker 服务，让容器网络支持 v6。如果镜像源或依赖服务只走 v4，配合 WARP 或 DNS64 才能完整跑通。机器本身有原生 IPv4 的话，这一步可以省掉。
